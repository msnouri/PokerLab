Source review + new matches / November 11, 2026

Does S55 beat the GitHub models?

There is no general evidence that it does. New tests support an advantage over specific example policies in our eight-player tournament format, and expose a substantial weakness in heads-up play.

What actually ran: 70,000 heads-up hands, 35,000 eight-player reset-stack hands, and 896 eight-player tournaments (138,187 tournament table-hands). S55 was frozen before testing. Seven external example-policy configurations were tested. Zero pretrained DQN/CFR models were tested.

Interpretation: S55's tournament advantage does not carry over to heads-up chip profit. Against the most aggressive threshold policy it loses about 164 big blinds per 100 heads-up hands. Its original success against our related heuristic opponents was not proof of broad strength.

Why the results differ

By code inspection, a plausible contributor is S55's narrow all-in calling rules and random-opponent equity assumption. It does not fully update its calling range when an opponent repeatedly shoves weak holdings. That can be costly heads-up, where folding repeatedly surrenders blinds. In a top-three payout tournament, survival and avoiding other players' confrontations have value. These are interpretations of code and outcomes, not a causal ablation study.

S55 is a book-inspired rule policy with sampled equity. It is not a learned game-theoretic strategy, and no exploitability guarantee was established. A working CFR implementation or a neural-network architecture does not by itself establish an opponent's strength either; game match, trained artifact and reproducible evaluation matter.

Exactly what the adapter changes

  • Preserved: upstream policy method bodies, threshold comparisons, action priority and the discrete action choices; original source blob hashes are pinned.
  • Replaced: the Gym engine with PokerKit legal actions/settlement, and native equity calculations with the same equity feature used by S55 (our preflop asset plus 48 postflop samples).
  • Bet mapping: upstream half-pot/pot/twice-pot actions mean an additional contribution of that size. Only targets legal under standard no-limit rules are offered; fractional chips are rounded down. All-in uses the maximum legal target. The original Gym per-player raise cap is not imposed.
  • Not compared: the repositories' complete equity pipelines, the native Gym game implementation, trained neural policies, CFR strategy quality, external API latency or the official competition variant.

Consequently these are adapted example-policy results. Calling them a victory over the full Neuron Poker neural model would be inaccurate.

Game and statistical controls

  • Heads-up: 5,000 independent shuffled deals per opponent, each played from both seats, totaling 10,000 hands. Start stack 2,000 each hand, blinds 10/20, no rake.
  • Eight-player cash: 5,000 independent table-hands per opponent, seats rotated, stacks reset to 2,000 each hand, blinds 10/20.
  • Eight-player tournaments: 128 independent tables per opponent. Starts 2,000, 25-hand levels with big blinds 20/30/40/60/100/150/200/300, cap 200 hands. Assumed payouts 50/30/20; exact ICM for remaining payouts at the cap.
  • S55 parameters were not tuned after seeing these results. Seeds are distinct from the earlier experiments. No deadline folds are imposed. All hands check chip conservation and policy actions must be legal.
  • Ordinary 95% intervals are in the primary CSV files; simultaneous 95% bounds across all 21 comparisons are in simultaneous_intervals.csv. All seven tested tournament configurations remain above parity under those adjusted bounds.

Practical judgment

Keep S55 as a measured baseline for our assumed eight-player tournament, rather than treating it as a superior general poker model. The most useful immediate improvements are stronger conditioning on observed opponent aggression, format-specific preflop/all-in ranges and evaluation against independently trained policies. PokerKit remains useful as infrastructure; NoRegret is relevant for solving tractable games or abstractions, not a plug-in eight-player opponent.

A fair next trained-model comparison requires its exact checkpoint, compatible input encoding/action mapping and its intended game. Heads-up and eight-player outcomes must remain separate. No recommendation here depends on stars or repository names.

Files and reproduction

The accompanying archive contains the benchmark, pinned source downloader, raw hand/table outcomes, settings, inventories and this report. It requires the original poker_lab package next to github_comparison, or an explicit POKER_LAB_PATH.

python download_sources.py
PYTHONHASHSEED=0 python benchmark.py --deals 5000 --tables 128 --workers 8
python build_report.py

The downloader verifies Git blob hashes. Upstream sources are downloaded separately and are not redistributed in the archive. No poker client is automated, no game service is contacted, and no submission is made.

Evidence boundary: source review establishes architecture and artifact availability; only the reported matches establish performance in this specific adapter and game configuration.
